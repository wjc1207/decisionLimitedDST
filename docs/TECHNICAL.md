# JEV DST Agent 技术说明（1.4.2）

[项目首页](../README.md) · [English technical reference](TECHNICAL.EN.md)

以下命令均从项目根目录（`jev_dst_agent`）运行。

本项目通过一个《饥荒联机版》客户端 Mod，将游戏状态提供给 JEV，并执行 JEV 选择的有限动作。控制器只能执行本文明确列出的动作。

## 输出的游戏状态

客户端 Mod 每秒向 `client_log.txt` 写入一条 JSON 记录，内容包括：

- 天数、昼夜阶段和世界时间；
- 生命值、饥饿值和理智值；
- 背包与已装备物品；
- 当前能否制作火把或营火；
- 附近的有用物品、资源、光源和威胁；
- 持久化的前沿导航状态、目标点和当前路段。

较短的记录以 `[JEV_DST_STATE]` 开头。超过单行日志安全长度的记录会分成多条 `[JEV_DST_CHUNK]` 输出，由 Python 端按编号拼回完整 JSON。游戏日志在每段末尾追加的制表符会在拼接前去掉。控制器和状态监视器只接受完整且可解析的记录；旧版 Mod 留下的截断行会被忽略。

## 安装 Mod

将整个 `jev_dst_agent` 文件夹复制到《饥荒联机版》的 `mods` 目录。本机检测到的目标位置是：

```text
C:\Program Files (x86)\Steam\steamapps\common\Don't Starve Together\mods\jev_dst_agent
```

启动游戏，打开“模组”，启用 **JEV DST Agent**，应用更改，然后进入本地或私人世界。

## 查看实时状态

在项目根目录打开 PowerShell，然后运行：

```powershell
python.exe .\watch_state.py
```

如需查看完整 JSON 记录：

```powershell
python.exe .\watch_state.py --full
```

## 有限控制

`controller.py` 支持移动、采集、制作、劳动、进食、烹饪和战斗操作：

```powershell
python.exe .\controller.py status
python.exe .\controller.py move up --seconds 0.25
python.exe .\controller.py interact
python.exe .\controller.py collect grass
python.exe .\controller.py cook
```

`collect` 会选择观测范围内最近的匹配 prefab，通过短促的 WASD 输入接近目标，每次移动后等待新状态，然后按普通动作键。若程序运行被中断，`stop` 会释放所有移动键。JEV 的安全散落资源候选项包括燧石、木头和石头。

采集时，人物会先接近到目标 1 个世界单位以内，再按空格键。若资源来源失去 `pickable` 标记，或散落物从世界中消失，即判定采集成功；如果交互没有完成，控制器会重试，不会直接进入下一轮 JEV 循环。

草丛、树苗和浆果丛会提供明确的实时 `pickable` 值，资源耗尽时不会作为 JEV 候选项。控制器在按空格键前会等待更新的状态，并再次检查相同的值。如果背包中的草、树枝或浆果数量增加，即使采集后的植物实体仍留在世界中，也能证明采集已经完成。

控制器会把所选采集目标的 GUID 保留到执行阶段，避免更近但已耗尽的植物替换原来的有效目标。如果该 GUID 在执行前已不可用，控制器会改选同一 prefab 中当前最近且仍可采集的植物。

## 离线自动测试

无需启动游戏、调用 JEV 或发送任何键盘输入，即可运行完整回归测试：

```powershell
python.exe .\run_tests.py
```

测试使用模拟状态和模拟游戏输入，覆盖已耗尽与可采集资源的选择、GUID 传递、后备目标选择，以及植物实体仍存在但背包物品增加时的采集完成判断。

采集移动采用按距离缩放的按键时长：远距离时最长为 1 秒，接近交互范围时缩短到 0.18 秒。正在追击玩家的敌人进入 5 个世界单位内会立即中断采集。遭到近距离追击时，没有武器的角色只会获得逃跑动作；背包中有武器时可以先装备，只有手上已经装备武器时才会出现攻击动作。逃跑在遭到追击时始终可用，包括夜晚。

一次逃跑不是短按一次方向键，而是一个有上限的连续过程：Mod 在追击发生时，沿八种实际 WASD 方向用 `IsPassableAtPoint` 探测最多 6 单位的可通行路线；控制器选择能拉开与追击者距离的方向，必要时沿海岸侧向移动，而不固守“正背对敌人”的方向。每段之后读取角色真实位移并重新选路；若按键后几乎没移动，本次逃跑会避开该方向。无可通行方向时停止并报告错误，不会继续无意义地撞边界。连续两次观测不到追击者时停止，最多执行 8 段。逃跑依赖 Mod 1.4.1 新增的 `navigation.escape_routes`；更新 Python 后也必须更新并重新加载游戏 Mod。

探索现在也会避开近期见到的敌人：Mod 对具有 `hostile` 标签、尚未攻击玩家的实体标记 `potentialThreat`，并记住其位置 90 秒。距离敌人 14 单位内的前沿不参与选择，14–26 单位的前沿有逐渐减弱的分数惩罚；已选目标若变得危险会被放弃。邻区与道路的下一段也会检查危险范围。控制器在实际按键前再次检查整段路线及最新观测，避免刚逃开又沿原路走回敌人身边。敌人消失后记忆会过期，避免永久封锁区域。

光源管理根据昼夜阶段工作：白天和黄昏不会提供装备火把动作；如果火把已经装备，卸下火把仍是 JEV 可以选择的普通候选项之一。夜晚只有在 8 个世界单位内没有燃烧中的营火或石篝火时，才会提供装备火把动作。营火只能在夜晚建造；如果身边已有燃烧中的营火或石篝火，则隐藏装备火把动作，但仍提供卸下火把动作，不会强制卸下。除非正在逃离迫近的敌人，否则夜晚没有装备火把时不能离开光源移动。

火把操作是带有执行后验证的语义化 Mod 动作：

```powershell
python.exe .\controller.py craft-torch
python.exe .\controller.py equip-torch
python.exe .\controller.py unequip-torch
```

只有状态数据表明当前可以制作火把，并且背包或手上没有火把时，JEV 候选列表才会包含 `craft_torch`。只有在夜晚、已有火把、火把未装备且附近没有燃烧中的营火或石篝火时，才会出现 `equip_torch`。白天或黄昏装备着火把时，以及夜晚身边有燃烧中的营火或石篝火时，会出现 `unequip_torch`。

`craft_torch` 制作成功后，如果游戏自动把新火把装备到手上，而当前仍是白天或黄昏，控制器会在同一个动作内验证并卸下火把以节约耐久；若已入夜，则保持装备。JEV 不需要为这一步额外选择 `unequip_torch`。

其他有限动作：

```powershell
python.exe .\controller.py craft-axe
python.exe .\controller.py craft-pickaxe
python.exe .\controller.py chop
python.exe .\controller.py mine
python.exe .\controller.py eat
python.exe .\controller.py build-campfire
python.exe .\controller.py attack
python.exe .\controller.py equip-weapon
python.exe .\controller.py flee
```

只有状态数据发现有效的敌对或怪物目标，并且武器已经装备时，才会提供攻击动作。攻击使用游戏原生的 `Ctrl+F`，不依赖鼠标坐标或 Mod 的 F10 桥接。营火建造遵循游戏原生的两阶段流程：先缓冲或制作配方，再放置营火。

砍树和采矿会持续到 Mod 实际选中的目标被完整采集，然后在该目标 4 单位内拾取最多 12 堆掉落物：木头、松果、桦栗、硝石、燧石、金块等常见产物，以及本次作业后新出现的其他散落物。原本就在附近的无关物品不会因此被自动拾取；敌人靠近或夜里没有随身光源时停止拾取。Mod 通过状态中的 `work` 序号、目标 GUID、位置与完成状态向控制器确认，不再让两端独立猜测目标。只有状态数据证明对应的基础工具有足够耐久完成整项工作时，JEV 才会看到相应动作：普通树木按最多砍 15 下保守计算；常见矿石使用游戏定义的 6、4 或 2 次敲击。进食采用保守的前期安全食物白名单，包含烹饪产出的熟肉和熟小肉。

`cook_food` 只在 6 单位内有正在燃烧的营火或石篝火，且背包里有生肉、小肉、浆果或胡萝卜时提供。Mod 再次确认食物带 `cookable` 标记和火源可烹饪，使用游戏原生 `COOK` 动作，一次只处理一份。控制器等到背包熟食数量增加才确认成功；已煮熟的食物和危险食材不会触发该选项。

选择 `eat_safe_food` 时，若已有熟食就直接吃；若只有可烹饪的生食且 6 单位内有可用火堆，则自动先烹饪一份、验证熟食入包，再吃一份。烹饪失败但仍有可安全食用的浆果或胡萝卜时，会退回直接进食；不会把生肉当成安全退路。

## 候选项裁剪原则

候选项裁剪不会替 JEV 选择动作。它只会移除当前不可用、在当前情境中没有意义，或被明确安全约束禁止的动作。JEV 仍会对所有剩余的有意义动作进行排序并选择。

例如，白天或黄昏装备着火把时，会提供 `unequip_torch`，因为收起火把可以节省燃料；没有装备火把时则不会提供 `equip_torch`，因为白天举着点燃的火把没有实际收益。夜晚且没有其他光源时，两者关系反转；站在燃烧中的营火或石篝火旁时，装备火把又会因为重复而被省略。

火堆是固定光源：夜晚没有装备火把时，即使附近有燃烧的火堆，也不会提供区域探索、沿路探索或采集，以免走出照明范围。控制器在移动前和每段移动后再次检查；若途中入夜且没有火把，就停止后续路段或采集步骤。逃离敌人仍可优先于这项约束。

同样，资源耗尽的植物、不可用的配方、耐久不足的工具，以及被世界地图 API 判定不可通行的前沿路段，都不会作为候选项出现。裁剪层只判断哪些操作当前有意义，不判断哪个有意义的操作最好。

## JEV 决策

发给 JEV 的提示区分硬限制与决策建议，并明确每个候选项是一次完整的有界动作：砍树/采矿包含附近掉落物拾取，`eat_safe_food` 在需要时包含先烹饪再吃，单独的 `cook_food` 用于准备稍后食用的食物。提示还提供饥饿比例、可安全食用食物数量和附近可用火源，便于 JEV **快速选择下一步**；JEV 不负责生成每日计划，规划建议也不会替 JEV 选择。

## DeepSeek 每四分之一天规划（可选）

在 `.env` 中填写 `DEEPSEEK_API_KEY` 后，使用 `--loop --execute` 的控制循环会根据 `world.time`（一天内的 0–1 进度）在每天的四个区间各请求一次简短计划：0–25%、25–50%、50–75%、75–100%。启动时若已进入中途区间，会直接为当前区间规划，不补发过去的请求。模型默认是 `deepseek-flash`；可用 `DEEPSEEK_MODEL` 和 `DEEPSEEK_API_URL` 覆盖。规划输入包括当前状态、本次运行中最多 40 条最近行动结果摘要，以及项目根目录的 [DSTKnowledge.txt](../DSTKnowledge.txt)；不会上传逐秒重复的游戏日志。知识文件列出经本机游戏配方脚本核对的常用配方和少量生存常识，可直接编辑；每次规划都会重新读取。程序不打印 API 密钥。没有密钥时仍可单独使用 JEV。

规划请求不会等待在 JEV 的决策路径上：计划未返回时 JEV 照常行动，返回后作为 `daily_plan` 加入 JEV 的状态输入。计划只说明当前四分之一天的目标、少量步骤和优先事项；当前游戏事实、候选动作与安全规则始终优先。跨入新区间后旧计划不再发送给 JEV，上一季度迟到的回复也不会覆盖当前计划。连续两次执行同一动作失败，或成功建造科学机器后，会触发区间内重规划（至少间隔 60 秒）。若 DeepSeek 因长度截断或空内容无法给出完整 JSON，后台最多重试一次；仍失败时 JEV 继续运行，下一区间再试。行动摘要只保存在当前 Python 进程的内存中，重启后会重新规划。

终端会输出 `daily_plan_requested day=… quarter=… knowledge_chars=…`，完成时输出 `daily_plan_ready`、DeepSeek 请求耗时 `response_time`，以及规划 JSON 的前 240 个字符 `preview`；超长内容以省略号标记。重试时会输出 `daily_plan_retry` 和返回的结束原因；最终失败时也会显示耗时、结束原因和错误。

将 TypeSafe API 密钥写入 `.env`，格式参见 `.env.example`。默认只进行试运行，不发送游戏输入：

```powershell
python.exe .\jev_agent.py --show-probabilities
```

确认试运行结果后，再添加 `--execute`：

```powershell
python.exe .\jev_agent.py --execute
```

持续自动控制使用：

```powershell
python.exe .\jev_agent.py --loop --execute
```

循环默认没有冷却时间，每个动作完成后会立即重新感知。可使用 `--interval 1` 或其他不超过 60 秒的值增加冷却时间。发生错误时仍会使用至少 1 秒的指数退避，避免形成高速失败循环。

砍树、采矿、采集和建造等长动作会先执行完毕，再开始下一轮，因此动作不会重叠。进入第 2 天不会结束任务：循环会持续运行，仅在角色死亡或按 `Ctrl+C` 中断时停止。瞬时错误会采用有上限的指数退避后重试。

## 区域与道路探索

JEV 现在可以在两个有意义的探索动作间选择：`explore_current_region`（探索当前地皮类型的前沿）和 `explore_other_region`（沿已发现的道路寻找其他地皮类型）。后者只有 Mod 实际观测到可通行的道路下一段时才会出现；没有路时不会凭空生成这个选项。道路不是地形边界，也不保证通向新地形。

Mod 只在角色周围查询地皮、区域拓扑 ID、道路和可通行地形，不读取整张未探索地图。拓扑 ID 仍作为世界生成分支信息上报，但不再被当作森林、草地等地形。`navigation.current_biome` 从实际地皮识别森林、草地、稀树草原、沼泽、岩石地、落叶林、沙漠和泥土地；道路或人造地板上会参考相邻自然地皮，连续两次采样改变才确认新区。`biomes_seen` 记录已观察到的地皮类型。“出生地”“混合地”需要周围地形和位置上下文，绿洲与普通沙漠也无法只靠沙漠地皮区分，因此不会单凭一块地皮推断它们。已观测道路被记成相连的路段；走到岔口或尽头时，可以沿走过的路回溯到尚未探索的分支，但不会为单纯重复走旧路提供探索选项。

现在还会建立逐步发现的区域图：以“拓扑 ID + 地皮类型”为节点标识，记录已观察的网格数量、实际进入次数和见过的资源；两个节点间只有观测到可通行的边界或实际通过时才记为相邻。每对节点最多保留三个入口。`navigation.graph` 只输出当前节点、最多四条可执行的邻区路线及返回路线，不把整张地图塞进每条状态日志。JEV 可以选择 `explore_adjacent_1` 等选项进入已发现的邻区，也可以选择 `return_previous_region` 沿记录的连接回到上一个区域。提示会把“实际见过的资源”和“按地皮推测可能出现的资源”明确分开。

邻区与返回动作每次只走下一段已验证可通行的路；直线受阻时会尝试用已观测的同一区域网格绕行，走完后仍交回 JEV 决策。道路探索保留用于寻找尚未发现的 worldgen 区块；进入新图节点时会停下，让 JEV 重新决定。当前节点标识还不是严格的连通分量：同一个拓扑块内、同种地皮的两片分离地形可能暂时共用节点 ID；路线只在发现可通行连接后才提供。区域图目前只保存在本次游戏内存中，重进世界会重新观测。

探索当前地形仍使用局部前沿：Mod 将附近地形划分为边长 4 个单位的网格，记录已观测格子，并只考虑与当前地皮类型相同的可通行前沿。一个已知可通行、且至少与一个未知格子相邻的格子称为“前沿”。当前基础评分公式为：

```text
score = information_gain * 10 - distance * 0.5 - visits * 6
```

分数最高且可到达的前沿会成为当前地形探索的持久目标。即使中间执行了采集、制作或其他动作，该目标也会保留，直到抵达目标、地皮类型改变或下一个路径段失效。失效目标会进入 30 秒黑名单，然后系统再选择其他前沿。沿路探索不使用这个分数，而是沿已观测道路寻找最近的未走路段，必要时经过走过的路段回溯。

探索当前地形每次只走下一个最多 4 单位的路段。沿路探索会在一次 JEV 决策内连续跟随 Mod 实时更新的道路点，最多 8 段、累计最多 10 单位，而不是每走约 2 单位就重新请求 JEV。Mod 每隔 0.75 单位使用 `TheWorld.Map:IsPassableAtPoint` 检查路段；无效路段不会提供给 JEV。沿路移动在每个道路点前最多进行四次短促按键，每次松键后等待新状态并修正方向。到达判定允许误差：前沿目标 1.5 单位，道路点 1.25 单位，不再为精确踩中坐标而反向补走。控制器在发现近处新资源并至少走了 4 单位、敌人、地皮类型或昼夜阶段变化、携带食物且饥饿危险、夜间失去随身光源或道路结束时提前停下，让 JEV 重新选择。若同一道路点连续两段没有明显进展，控制器会通知 Mod 将它列入 30 秒黑名单。

方向键只是根据目标向量推导出的执行细节。可使用 `--move-seconds` 调整走完一个 4 单位路段的时长；默认值为 1 秒，可用范围为 0.2–2.0 秒。

装备火把采用与手动点击背包火把相同的物品格动作，而不是动作系统的自动装备辅助功能。

## 执行阈值与安全规则

JEV 提示还明确建议白天和黄昏卸下火把，以节省耐久。

饥饿低于最大值的 30% 且背包已有安全食物时，等待、探索和可选采集会从候选项中移除；JEV 仍需选择下一步，但此时只保留进食，以及确有需要时的逃跑或夜间照明。紧急进食的默认执行阈值为 `0.00`，普通进食仍为 `0.25`；若手动指定 `--min-confidence`，则仍以用户设定为准。没有携带食物时，不会禁止寻找食物的探索动作。

默认执行阈值：

- 逃跑、等待，以及饥饿低于 30% 时的紧急进食：`0.00`；
- 探索当前区域或其他区域：`0.15`；
- 攻击：`0.45`，且没有装备武器时不可用；
- 其余动作（包括采集、烹饪、进食、制作和建造）：`0.25`。

可通过 `--min-confidence` 统一覆盖这些阈值。夜晚没有装备火把时，硬性安全规则会阻止移动或采集；逃离迫近敌人是唯一例外。Git 会忽略 `.env`，发布压缩包也会刻意排除该文件。
